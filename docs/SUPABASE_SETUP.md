# Подключение кабинета преподавателя к Supabase

В Supabase сейчас уже настроены Auth и таблица `profiles`. Миграция создаёт
отдельные таблицы для личного кабинета преподавателя:

- `teacher_classes` и `class_students` — классы и списки учеников;
- `teacher_lessons` — уроки с блоками заданий;
- `class_lesson_assignments` — назначения уроков классам;
- `student_lesson_progress` — ответы и прогресс для каждой пары «ученик + урок»;
- `teacher_workspace_settings` — отметка о переносе данных браузера.

Старая таблица `teacher_materials`, больше не используемая интерфейсом, удалена
миграцией [`20261017_remove_legacy_teacher_materials.sql`](../supabase/migrations/20261017_remove_legacy_teacher_materials.sql).

## Применить схему

1. Откройте Supabase Dashboard → проект → **SQL Editor** → **New query**.
2. Скопируйте и выполните содержимое
   [`supabase/migrations/20261014_teacher_workspace.sql`](../supabase/migrations/20261014_teacher_workspace.sql).
3. Откройте SlovaSofi через HTTP/HTTPS (например, Live Server), войдите в
   аккаунт преподавателя и перейдите в кабинет. Страница не должна открываться
   через `file://`.
4. После входа кабинет загружает данные из Supabase; старые локальные демо-данные
   автоматически не импортируются и не показываются в аккаунте.
5. Проверьте добавление класса или урока, обновите страницу и убедитесь, что
   запись осталась в кабинете.

Миграция использует только текущую сессию пользователя через `auth.uid()` и
включает RLS-политики: преподаватели работают только со своими данными.
Не вставляйте в браузер или клиентский код `service_role`-ключ. Для приложения
достаточно publishable/anon ключа в `supabase-config.js`.

## Редактор и предпросмотр заданий

Каждый раскрытый блок задания содержит форму редактирования и живой
предпросмотр. На узком экране предпросмотр расположен под формой. Изменения
текста, пунктов и корректных настроек сразу отображаются справа; пробные
ответы в предпросмотре не сохраняются в прогресс ученика.

В разделе «Расширенные настройки» находится JSON — технический формат
дополнительных параметров задания. Обычные текстовые задания можно создавать
без редактирования JSON. Для словаря массив `words` задаёт слова и переводы,
для интерактивного изображения массив `hotspots` задаёт координаты и подписи
меток. Примеры формата показаны в поле настроек. Уже сохранённые параметры
не требуется удалять. Ошибка JSON показывается под полем; до исправления
используется последняя корректная конфигурация.

Предпросмотр записи произношения показывает интерфейс без доступа к микрофону;
запись и отправка доступны в настоящем уроке ученика. Выбор ошибочного слова,
меток, переворот карточек и обычные тренировочные ответы работают локально.
Ограничения числа прослушиваний, проверка ошибок по JSON и оценка словаря
остаются функциями ученического урока, а не редакторского предпросмотра.

## Приглашение учеников

1. После основной миграции выполните в SQL Editor
   [`supabase/migrations/20261015_student_invites.sql`](../supabase/migrations/20261015_student_invites.sql).
   Она добавляет email ученика и политики, позволяющие ему видеть только свой класс.
2. В Supabase → **Authentication → URL Configuration** добавьте полный адрес
   страницы приглашения в **Redirect URLs**, например
   `https://example.com/SlovaSofi/student.html`. Учитывайте путь сайта, если он
   размещён не в корне домена.
3. Установите Supabase CLI и войдите в него (`supabase login`), затем свяжите
   рабочую папку с проектом (`supabase link --project-ref <project-ref>`).
4. Задайте `APP_URL` как базовый адрес сайта без имени страницы, например
   `https://example.com/SlovaSofi/`, и разверните функцию:

   ```powershell
   supabase secrets set APP_URL=https://example.com/SlovaSofi/
   supabase functions deploy invite-student
   ```

   Для локальной проверки используйте базовый адрес локального HTTP-сервера
   вместо опубликованного URL. Он должен совпадать с источником страницы.
5. В разделе **Authentication → SMTP Settings** настройте SMTP-провайдера.
   Пока SMTP отправка не настроена, Supabase может ограничивать приглашения
   тестовой почтой или возвращать ошибку отправки. Resend для рабочего режима
   требует подтверждённый домен отправителя.
6. Откройте кабинет преподавателя по HTTPS, откройте раздел классов и нажмите
   **«Пригласить ученика»**. Для нового email Supabase отправит письмо со ссылкой
   создания пароля. Повторное приглашение уже добавленного в класс email пока
   блокируется, чтобы не создавать дубли в списке.

Не публикуйте `service_role` и не добавляйте его в `supabase-config.js`. Edge
Function использует серверные переменные Supabase. Страница `student.html`
показывает ученику только его классы и назначенные уроки. Ученические уроки
загружаются Edge Function `student-lessons`; она проверяет назначение и возвращает
задания без правильных ответов. Ответы и прогресс сохраняются сервером в
`student_lesson_progress`.

## Проверка заданий и восстановление пароля

1. Разверните серверную функцию проверки заданий:

   ```powershell
   supabase functions deploy student-lessons
   ```

   Для локальной проверки установите `APP_URL` равным origin локального HTTP-сервера,
   с которого открыт кабинет, и используйте тот же origin для опубликованной версии.
2. В Supabase → **Authentication → URL Configuration → Redirect URLs** добавьте
   полный адрес страницы сброса пароля, включая путь проекта:
   `https://alm1e.github.io/SlovaSofi/reset-password.html`.
   Если сайт размещён по другому адресу, укажите адрес своей страницы
   `reset-password.html`. Адрес страницы приглашения также должен оставаться в списке.
3. На странице входа выберите **«Забыли пароль?»**, укажите email и откройте ссылку
   из письма. На странице `reset-password.html` задайте новый пароль (не менее
   8 символов). Supabase Auth отправляет ссылку восстановления; пароль нельзя
   прочитать из базы данных.
4. Для проверки интерактивных уроков назначьте урок классу, войдите как ученик и
   отправьте ответы. Обновите страницу урока: ответы должны восстановиться, а
   завершение выставляется после правильного выполнения всех оцениваемых заданий.
