# Журнал действий и история уроков

## Включение

1. После предыдущих миграций выполнить один раз `supabase/migrations/20261119_audit_and_lesson_versions.sql` в SQL Editor. Миграция создаёт первую версию уже существующих уроков. Автор для начальной версии неизвестен: прошлые события не выдумываются.
2. Обновить серверные функции:

```sh
supabase functions deploy manage-teachers
supabase functions deploy invite-student
```

3. Опубликовать изменённые JS, CSS и teacher.html. Новый файл assets/js/teacher-history.js должен быть опубликован вместе с teacher.html.

Сначала SQL, затем серверные функции и сайт. Рабочая база не изменяется автоматически от изменения локальных файлов.

## Где искать

- «Классы → Журнал действий» показывает доступные события с подгрузкой по 50 строк.
- Ссылка «Журнал действий» в карточке класса ограничивает журнал этим классом.
- «История версий» доступна в списке уроков и в открытом уроке в режиме просмотра.
- «Посмотреть» показывает заголовок, уровень и текст заданий/ответов выбранной версии. Это текстовый просмотр, не интерактивный запуск старого урока.
- «Восстановить эту версию» создаёт новую текущую версию. Перед восстановлением нужно сохранить локальные изменения редактора.

## Что записывается

Создание, изменение и удаление уроков; архивация, восстановление и изменение классов; изменения списка учеников, назначений и календаря; изменения ролей и прав редактора. События записываются триггерами PostgreSQL, независимо от кнопки сайта. Ученики не имеют доступа к журналу и историческим ключам ответов. Ответы учеников не копируются в журнал.

Версии создаются только при изменении title, unit, activities или владельца урока. Автосохранение неизменённых уроков не создаёт версии, не пишет лишние события и не меняет updated_at. Каждая версия содержит полный снимок материала; объём базы растёт с числом и размером изменений. Автоматическое удаление истории не включено.

Восстановление проверяет актуальный updated_at и блокирует строку урока на время транзакции. При чужом изменении с момента открытия истории действие отклоняется. Назначения, списки учеников и записи прогресса не удаляются. Изменённый состав заданий может повлиять на отображение прежних ответов: идентификаторы заданий восстанавливаются вместе с материалом.

История не удаляется вместе с уроком. Восстановление через интерфейс поддерживается для существующих уроков; возвращение удалённого урока отдельно не реализовано. Восстановление создаёт обычное событие изменения и дополнительное событие восстановления с номером источника.

## Доступ

Администратор видит весь журнал. Директор видит журнал существующих школьных классов и общих уроков, но не личных классов или изменений ролей. Учитель видит события своих классов и общих уроков. История общей библиотеки доступна сотрудникам, а восстановление — только тем, кому разрешено редактировать уроки.

Историю и журнал нельзя редактировать из браузера. Права владельца базы и service_role остаются административными правами и не заменяют роль сайта.

Автор определяется по auth.uid(), а не из параметров браузера. Изменение ролей проводится RPC set_staff_access под JWT администратора; изменения списков учеников в invite-student выполняются под JWT проверенного вызывающего пользователя. Технические изменения без пользователя помечаются как «Система». Имя берётся из profiles или метаданных аккаунта; если оно не заполнено, показывается краткий идентификатор сотрудника.

## Проверки

`node --test assets/js/*.test.js` проверяет API, безопасное отображение снимков и существующие функции. `tools/verify-school-scope.cjs` проверяет реальные миграции в изолированном PostgreSQL PGlite: снимки, отсутствие дублей, восстановление, запрет подделки, изоляцию личных классов, отсутствие доступа ученика, конкурирующую ревизию и сохранность ответов/назначений. tests/browser/teacher-ui.js проверяет окна, просмотр, восстановление, конфликт, поздние ответы и пагинацию. Серверные функции нужно дополнительно проверить после развёртывания.
