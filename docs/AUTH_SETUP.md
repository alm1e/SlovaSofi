# Подтверждение email

При регистрации `assets/js/auth.js` передаёт в Supabase адрес соседней страницы
`login.html` через `options.emailRedirectTo`. Адрес сохраняет домен, порт
и папку проекта, поэтому подходит для Live Server и GitHub Pages.

## Настройка Supabase

В Authentication → URL Configuration:

1. Установите Site URL на адрес опубликованной страницы входа.
   Если используется адрес из заметок проекта:
   `https://alm1e.github.io/SlovaSofi/login.html`.
2. Добавьте тот же полный адрес в Redirect URLs.
3. Для локальной проверки добавьте полный адрес `login.html` из Live Server,
   например `http://127.0.0.1:5500/login.html`. Это пример: домен, порт
   и папка должны совпадать с адресом в браузере. `localhost` и `127.0.0.1`
   — разные адреса.

Без разрешённого Redirect URL Supabase может использовать Site URL.
Открывайте сайт через HTTP/HTTPS, а не двойным щелчком через `file://`.
Локальная ссылка работает только на устройстве с запущенным сервером;
для подтверждения с телефона используйте опубликованный сайт.

## Проверка

1. Загрузите изменённый `assets/js/auth.js` на сайт или откройте проект в Live Server.
2. Проверьте настройки URL выше и отправьте новую регистрацию тестового
   пользователя через сайт. Старые письма содержат прежние ссылки.
3. Откройте ссылку из нового письма. Должна открыться страница входа SlovaSofi.
4. Проверьте вход с email и паролем. Пока он показывает «Вход выполнен»:
   личный кабинет ещё не реализован.

Если переход по-прежнему неверный, проверьте шаблон Confirm signup в Supabase:
стандартная ссылка подтверждения использует `{{ .ConfirmationURL }}`.
Обычная ссылка на Site URL сама по себе не подтверждает email.
Для диагностики достаточно адреса страницы до `?` и `#`; токены и пароли
передавать не нужно.

Настройки Supabase и реальный переход из письма не проверены локальным
изменением кода и требуют отдельной проверки в проекте.

Документация: https://supabase.com/docs/guides/auth/redirect-urls
